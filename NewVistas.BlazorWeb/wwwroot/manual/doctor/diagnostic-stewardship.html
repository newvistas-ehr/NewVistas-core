Diagnostic Stewardship — for the physician

Some working diagnoses turn out to be something else more often than others. This feature keeps count — from your own colleagues' recorded outcomes, at this site — and shows you a quiet line when the diagnosis you're entering has a track record worth knowing about. It is descriptive, not predictive: it reports what happened here, and never tells you what this patient has.

Where you'll see it

On the Problem List → Add Problem screen, immediately under the ICD-10 code field. It appears as you enter the diagnosis, which is the only moment the information can still change what you do. It is a single collapsed line you choose to open — never a pop-up, never a block on saving, and it does not take focus.

Most diagnoses show nothing at all. The line only appears when a diagnosis clears the statistical floors, or when there is a published, time-critical alternative worth naming. Silence is the normal state.

Reading it

Everything is given as counts of patients — "revised in 9 of 41 adjudicated episodes at this site" — with any percentage in brackets afterwards. That is deliberate. Numbers presented as bare percentages are read wrongly by clinicians far more often than numbers presented as counts of people, and the fix is the way the number is written, not more training.

Two kinds of entry can appear:

  • What it turns out to be — alternative diagnoses this one has been revised to here, with how many times. Some entries are marked time-critical and come from published literature rather than local counts; those appear even when this site has no data at all, because a rare and lethal alternative is exactly the case where silence would do the most harm.
  • Worth considering — results that arrived before a revision more often than they arrived in episodes that were not revised. Both figures are shown so you can judge the comparison yourself.
An important limit. A test listed here arrived before a revision — that does not establish it would have changed the diagnosis. The clinician who ordered the troponin already suspected a cardiac cause. This cannot be corrected statistically, so the wording is deliberately cautious and you should read it that way.

Recording how it turned out

On the problem list, any problem still awaiting an outcome offers "How did it turn out?". You can answer:

  • It was right
  • Same condition, more specific — the workup succeeded and you coded it more precisely (diabetes → type 2 diabetes; unidentified influenza → influenza with the virus typed). This is not counted as an error.
  • Same condition, less specific
  • It was something else — the working diagnosis was wrong. This is the only answer that counts toward the revision rate.
  • Resolved, never established
  • Don't know / lost to follow-up — counted as unadjudicated, and excluded from the rate entirely.

When you enter the code it actually was, the system pre-selects an answer for you. That is a suggestion only — change it if it is wrong. What gets counted is your judgement, never the system's guess about you.

Answering is optional and always skippable. It is deliberately not a required field: a mandatory box produces default-clicked answers, which are worse than no answer at all because nobody can tell them apart from real ones afterwards. The statistics are honest precisely because the answers are voluntary.

What this is not

  • Not a performance measure. The system records how many different clinicians contributed to a number, and nothing more. There is no per-clinician breakdown anywhere in the product, and that omission is deliberate and permanent.
  • Not a prediction about your patient. It is a frequency count over past episodes at this site. It carries no sensitivity, specificity, or validated accuracy, and the disclaimer on the panel says so.
  • Not conditioned on how your patient presents. The count is per diagnosis, not per presentation — "UTI is revised to sepsis N times here", not "in patients who look like this one". Weigh it accordingly.

When a code arrives for something that had none

If a patient was tracked in an emerging cluster and a real code is later issued for it, the coded diagnosis is added to their problem list citing the cluster it came from. Where they were carrying a single working diagnosis for the same illness, that one is marked superseded and linked to the new code — one condition with a history, not two overlapping diagnoses.

None of this counts as a misdiagnosis. The code set changed; nobody was wrong. A recode stays out of the revision-rate numerator and out of its denominator, so it cannot move the figures on this page in either direction.

The same applies site-wide: when a code-set change affects the whole population (as when U07.1 arrived for COVID-19), administrators run a bulk migration that recodes every affected chart with the same provenance — and, by the same rule, moves none of the statistics on this page.

Machine-suggested codes

Codes accepted from the note suggester arrive on the problem list at Unconfirmed certainty with a permanent machine-cited marker and the quoted note sentence as evidence. They open a diagnostic episode like any other assertion, so "how did it turn out?" applies to them too — which is exactly how a bad suggestion pattern would eventually show up in the revision statistics.

The evidence panel

Every problem row has an Evidence link. It opens what the diagnosis rests on: each piece of structured evidence with its polarity — supports, argues against, equivocal, or not assessed — plus its source (a lab result, a note, a recorded symptom, an exam finding), the observed value and date, and a machine-cited marker where a suggestion engine rather than a clinician made the citation.

"Not assessed" is the row worth pausing on. A chart is usually silent about what was never checked, and silence reads — wrongly — as negative. Recording "influenza PCR: not assessed" is a positive statement that the question is still open, and it is different in kind from a negative result, which argues against the diagnosis. The panel lets you record both, and displays them differently.

From the same panel you can add evidence: pick the polarity, pick a source record (recent labs, notes, and coded symptoms are offered from the chart) or describe an exam finding in free text, and optionally move the diagnosis's certainty in the same step. Adding evidence never counts as a revision — it is the workup proceeding, not a change of mind — so it can never move the revision statistics on this page.

Certainty on the problem list

Problems now carry a certainty — suspected, provisional, differential, or confirmed — shown next to the diagnosis. A suspected diagnosis no longer looks identical to a settled one on the list, which was a real source of misreading. A diagnosis later disproved stays in the record but drops off the active list.

Also in the WPF client

The same advisory and the same "How did it turn out?" prompt appear on the Problem List in the Windows desktop client, in the same places and with the same wording.
