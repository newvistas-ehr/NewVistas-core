Code-Set Migration (Bulk Recode)

When a code is retired or a new one is issued — the canonical example is U07.1 arriving for COVID-19 while every existing patient carried B34.2 — this screen (/bulk-recode) re-asserts every active problem under the new code, across the whole population, with full provenance and zero effect on any diagnosis statistic.

What one migration does, per patient

  • Patients already carrying the replacement code are left untouched — re-running a directive is a no-op, never a duplicate row.
  • Otherwise, one new problem is asserted under the replacement code, carrying the old problem's certainty and onset date, and citing the old assertion as machine-cited evidence.
  • Each old problem is superseded (it stays in the chart, linked, off the active list) with revision reason Recode.
  • Any open diagnostic episode closes as Recoded.
Nobody was wrong — and the numbers must say so A recode is a statement that the code set changed, not that any clinician was. Recoded episodes are excluded from the revision-rate numerator, its denominator, and the adjudication-coverage ratio. Without this, remapping B34.2 → U07.1 would have taught the statistics that B34.2 was "wrong" 100% of the time — a permanently poisoned figure. This is why the migration path is a dedicated tool and not a loop over the ordinary revision screen.

Running one

  1. Open Code-Set Migration in the admin sidebar.
  2. Enter the retired code, the replacement code, its official description, and the why — that sentence is quoted onto every chart the migration touches.
  3. Optionally cap the number of patients screened (useful for a trial run).
  4. Confirm. The run report shows recoded / already-coded / no-match / failure counts, and the run history is kept on this screen.
Guard rails The replacement code must exist in the site's loaded ICD-10 index (a typo applied at population scale is not recoverable); the narrative is required; and the operation needs the XUMGR security key. A patient whose read or write fails does not abort the run — failures are counted and reported, and a re-run covers them (idempotency makes re-runs safe).

Pre-feature charts

Problems recorded before diagnostic stewardship existed have no open episode. Their problems still recode normally — they simply have no episode to close, which the run report shows as episodes-closed being lower than the recoded count. That is expected, not an error.
